# pnAuth 1.0.0 — Unified Authentication for Velocity, BungeeCord and Paper

Первый полноценный релиз новой Kotlin-архитектуры pnAuth. Один игровой JAR поддерживает Velocity, BungeeCord и автономные Paper/Folia-серверы. Для больших сетей в релиз также входит отдельный pnAuth Hub.

pnAuth — это не только форма ввода пароля. Плагин управляет полным циклом допуска игрока: подключение, регистрация, вход, дополнительное подтверждение, ограничения до авторизации, безопасный переход на игровой сервер, восстановление и отзыв сессий, административные действия и синхронизация большой сети.

## Для кого этот релиз

- Для одиночного Paper/Folia-сервера, которому нужна собственная регистрация и авторизация.
- Для сети на Velocity или BungeeCord с отдельным auth/limbo и игровыми backend-серверами.
- Для нескольких proxy, использующих общую SQL-базу и Redis.
- Для большой инфраструктуры, где credentials должны находиться только в центральном pnAuth Hub.
- Для разработчиков сайтов и ботов, подключающих собственное подтверждение действий.

## Что входит в релиз

- `pnAuth-1.0.0.jar` — единый плагин для Velocity, BungeeCord и Paper/Folia.
- `pnAuth-hub-1.0.0.jar` — центральный auth-сервис для сетей из нескольких proxy/серверов.
- Native dialogs через PacketEvents.
- Регистрация, вход, смена пароля, выход и удаление аккаунта.
- TOTP 2FA и recovery-коды.
- Сессии по IP с безопасным отзывом после смены пароля.
- CAPTCHA и ограничения количества аккаунтов по IP.
- Title, subtitle, actionbar и настраиваемая анимация.
- Русская и английская локализация.
- MiniMessage, Adventure JSON, legacy `&`, нативный `§`, HEX, hover и click.
- Автономная Paper/Folia-авторизация с точкой ожидания и телепортацией после входа.
- Режимы сети `STANDALONE`, `SHARED_DATABASE`, `REDIS` и `HUB`.
- Долговечный cluster outbox с повторной доставкой событий.
- Внешнее подтверждение через Discord, Telegram, VK и custom HTTPS provider.
- Подробные примеры custom verification для PHP, Python, Node.js, Java/Spring и Go.

## Полный цикл игрока

При подключении pnAuth загружает аккаунт по UUID и имени, проверяет premium/trusted session и выбирает состояние:

- `UNREGISTERED` — игрок должен зарегистрироваться;
- `UNAUTHENTICATED` — требуется пароль;
- `TOTP_PENDING` — пароль принят, требуется второй фактор;
- `AUTHENTICATED` — доступ к игровому серверу разрешён.

До завершения входа pnAuth может удерживать игрока на встроенном PicoLimbo либо, в автономном Paper-режиме, в настроенной точке ожидания. После успеха proxy переводит игрока на backend, а Paper возвращает его в исходную позицию, на spawn или в custom-точку.

## Регистрация и пароли

- Настраиваемая минимальная и максимальная длина пароля.
- Опциональный повтор пароля при регистрации.
- PBKDF2, BCrypt и Argon2 с настраиваемыми параметрами.
- Автоматический rehash при входе после усиления настроек hashing.
- Ограничение числа неудачных попыток и временная блокировка.
- Опциональный IP ban после превышения лимита попыток.
- Пользовательская и административная смена пароля.
- Удаление аккаунта пользователем или администратором.
- Безопасная очистка текущей и доверенной IP-сессии после смены пароля.
- Пароли никогда не передаются через Redis или cluster events.

## Двухфакторная авторизация

- TOTP, совместимый с обычными authenticator-приложениями.
- Provisioning URI для добавления аккаунта.
- Подтверждение настройки первым TOTP-кодом.
- Одноразовые recovery-коды.
- Ограничение попыток и lockout второго фактора.
- Зашифрованное хранение TOTP secret.
- Отключение TOTP только после проверки пароля и действующего кода/recovery-кода.
- В HUB-режиме TOTP и recovery-коды обрабатываются только центральным Hub.

## Native dialogs и интерфейс

Для современных клиентов используется нативная dialog-система Minecraft через PacketEvents. Общая модель диалогов одинакова для Velocity, BungeeCord и Paper и поддерживает:

- notice, confirmation, multi-action, server-links и dialog-list;
- text, boolean, single-option и number-range inputs;
- dynamic custom actions;
- обработку submit-события, а не простое закрытие окна;
- title/subtitle, actionbar и bossbar;
- анимированные HEX-градиенты;
- настраиваемые fade-in, stay, fade-out и задержку результата;
- fallback на команды/чат там, где native dialog недоступен.

Транспорт учитывает реальную ClientVersion PacketEvents и безопасно очищает dialog при disconnect.

## Сообщения и оформление

Все платформы используют один Adventure-конвейер. Поддерживаются:

- MiniMessage;
- Adventure JSON;
- legacy-цвета с `&`;
- нативный символ Minecraft `§`;
- HEX/RGB;
- plain text для логов и внешних сервисов;
- hover events;
- click events и командные кнопки.

BungeeCord получает канонический Adventure-компонент через JSON, поэтому hover/click и RGB не теряются при преобразовании в `BaseComponent`.

## Команды

Основные пользовательские команды:

- `/register` (`/reg`) — регистрация;
- `/login` (`/l`) — вход;
- `/logout` — завершение сессии;
- `/changepassword` (`/changepass`) — смена пароля;
- `/unregister` (`/unreg`) — удаление аккаунта;
- `/totp` (`/2fa`) — настройка и управление вторым фактором;
- `/status` — состояние авторизации;
- `/auth` (`/pnauth`) — общий корень pnAuth.

До авторизации разрешены только auth-команды, указанные политикой доступа. Tab completion и обработка команд используют общий Kotlin-сервис, а платформы остаются тонкими адаптерами.

## Ограничения и защита до входа

На proxy pnAuth блокирует переход с auth-сервера на игровые backend-серверы, а также может ограничивать чат и команды.

На Paper/Folia отдельно настраивается блокировка:

- движения;
- чата;
- посторонних команд;
- взаимодействия с блоками и сущностями;
- разрушения и установки блоков;
- открытия инвентаря.

## Маршрутизация и limbo

- Встроенный PicoLimbo может автоматически запускаться вместе с proxy.
- Загружаемая native-библиотека проверяется по SHA-256.
- Поддерживаются несколько auth и backend routes.
- Доступны `LEAST_PLAYERS`, `FIRST_AVAILABLE`, `ROUND_ROBIN`, `RANDOM` и `FILLING`.
- Настраиваются общие и индивидуальные лимиты игроков.
- Forced hosts приводятся к единой нормализованной модели.

## Хранилища

Для одиночной установки доступна SQLite. Для сети предусмотрены JDBC, MySQL, MariaDB и PostgreSQL. Слой repository общий для всех платформ; настройки подключения и секреты не дублируются в адаптерах.

Ограничения количества зарегистрированных и одновременно активных аккаунтов по IP применяются централизованно. Для служебных адресов предусмотрены исключения.

## Режимы сети

### STANDALONE

Один proxy или Paper-сервер, локальная база, без внешней синхронизации.

### SHARED_DATABASE

Небольшая сеть использует общую SQL-базу. Служебная таблица событий передаёт изменения аккаунтов и отзывы сессий. Старые записи очищаются автоматически.

### REDIS

SQL остаётся источником истины, Redis Streams обеспечивает быстрый fan-out событий всем proxy. Каждый узел хранит собственную позицию чтения; consumer group не используется, поскольку событие должны получить все узлы. Доступны `redis://` и `rediss://` с проверкой TLS hostname.

### HUB

Proxy превращается в тонкий агент. Пароли, password hash, TOTP secret и recovery-коды находятся в SQL-базе Hub. Hub выполняет регистрацию, login, смену пароля, TOTP, premium и admission-проверки и не возвращает password hash игровым узлам.

## Долговечная синхронизация

События безопасности сначала атомарно записываются в локальный `cluster-outbox`. Если Redis, Hub или SQL-транспорт временно недоступен, событие остаётся на диске и отправляется повторно до подтверждения записи.

Обработка at-least-once и идемпотентна: повторный отзыв уже отозванной сессии безопасен. Изменённый пароль не откатывается из-за сбоя Redis. После восстановления связи узлы дочитывают поток и применяют пропущенные изменения.

## Внешнее подтверждение

Выбранные операции — LOGIN, REGISTER, CHANGE_PASSWORD, UNREGISTER, TOTP_DISABLE и PREMIUM_CHANGE — могут требовать дополнительного решения.

Встроенные transports:

- Discord webhook с кнопками;
- Telegram Bot API с inline keyboard;
- VK community messages;
- универсальный custom HTTPS provider.

Ticket имеет TTL, UUID игрока, operation, session generation и одноразовый статус. GET открывает безопасную промежуточную страницу, а окончательное решение принимается только POST-запросом, поэтому preview мессенджера не подтверждает вход случайно.

Custom provider получает `pnauth.verification.v1`; запрос подписывается HMAC-SHA256 по method, path, timestamp, nonce и SHA-256 исходного body. В репозитории есть пошаговые реализации для пяти популярных backend-стеков.

## Безопасность Hub

- Отдельный client-id и secret каждого узла.
- HMAC-SHA256 подпись каждого запроса.
- Timestamp tolerance.
- Одноразовый nonce и replay protection.
- Constant-time сравнение подписи.
- Ограничение размера body.
- Rate limit на клиента.
- `Cache-Control: no-store` и `X-Content-Type-Options: nosniff`.
- Программный запрет password/hash/token/secret/recovery/credential в cluster event attributes.

## Требования

- Java 21 или новее для Minecraft 1.21.x.
- Для Paper/Velocity 26.1+ требуется Java 25.
- PacketEvents 2.13.0 должен быть установлен на ту же платформу.
- Клиент Minecraft с native dialogs — 1.21.6 или новее.
- Для Redis рекомендуется `rediss://` вне локальной доверенной сети.
- Для Hub и custom verification обязателен HTTPS.

## Быстрая установка

1. Скачайте `pnAuth-1.0.0.jar`.
2. Установите подходящий PacketEvents:
   - `packetevents-velocity-2.13.0.jar`;
   - `packetevents-bungeecord-2.13.0.jar`;
   - `packetevents-spigot-2.13.0.jar` для Paper/Folia.
3. Поместите оба JAR в каталог `plugins`.
4. Запустите сервер один раз.
5. Настройте созданный русский `plugins/pnAuth/config.yml`.
6. Перезапустите сервер.

## Сетевая согласованность

SQL или pnAuth Hub является источником истины. Redis не хранит пароли, password hash, TOTP secrets или recovery-коды.

После смены пароля pnAuth:

1. сохраняет новый пароль в авторитетном хранилище;
2. очищает trusted-IP session;
3. немедленно отзывает текущую сессию;
4. атомарно сохраняет событие в `cluster-outbox`;
5. повторяет доставку, пока транспорт не подтвердит запись;
6. заставляет остальные узлы отозвать свои локальные сессии.

Старый пароль не возвращается при недоступности Redis. Повторные события безопасны и идемпотентны.

## Автономный Paper/Folia

Paper является полноценной платформой pnAuth без обязательного proxy. До входа можно блокировать движение, чат, команды, взаимодействие, блоки и инвентарь.

После авторизации доступны направления:

- `ORIGINAL` — исходная позиция игрока;
- `SPAWN` — spawn выбранного мира;
- `CUSTOM` — заданные координаты;
- `NONE` — без телепортации.

## pnAuth Hub

Hub централизованно хранит и проверяет credentials, TOTP и recovery-коды. Proxy не получает password hash. Запросы подписываются HMAC-SHA256 с timestamp и одноразовым nonce.

Запуск:

```bash
java -jar pnAuth-hub-1.0.0.jar /path/to/pnauth-hub
```

Рекомендуемая production-схема: Hub слушает `127.0.0.1` за HTTPS reverse proxy.

## Важные замечания

- Перед production-развёртыванием сделайте резервную копию базы и конфигурации.
- Для публичной proxy-сети обязательно защитите backend от прямых подключений.
- Полноценные самостоятельно размещаемые Discord/Telegram/VK command-боты не входят в 1.0.0; доступны transports подтверждения и универсальный custom provider API.
- Встроенный Hub event broker рассчитан на один экземпляр Hub. HA-кластер нескольких Hub потребует общей внешней очереди.
