# pnAuth 1.1.0 — Stable Native Dialogs & Unified Paper UI

pnAuth 1.1.0 — стабильное функциональное обновление единого Kotlin-плагина авторизации для Velocity, BungeeCord, Paper и Folia. Релиз закрывает проблемы, найденные при реальном тестировании native dialogs, обработки пароля, компонентов Adventure и интерфейса повторного входа.

Один `pnAuth-1.1.0.jar` работает на всех игровых платформах. Для крупных сетей отдельно поставляется `pnAuth-hub-1.1.0.jar`.

## Главное в 1.1.0

- Paper/Folia переведён на общий PacketEvents transport layer, уже используемый Velocity и BungeeCord.
- Диалог регистрации или входа стабильно открывается после асинхронной загрузки профиля.
- Нажатие кнопки формы передаёт введённые значения в auth-сервис и запускает реальную проверку пароля.
- Повторное открытие окна использует нативное custom action, а не скрытую команду игрока.
- Paper получил анимированную проверку пароля и отдельный итоговый title успеха либо ошибки.
- Исправлен вывод сырых MiniMessage-тегов и обратных слешей в чате.
- PacketEvents автоматически устанавливается и проверяется для всех поддерживаемых платформ.

## Исправления Paper/Folia

- Удалён отдельный транспорт через консольные `dialog show` и `dialog clear`.
- Устранена ошибка `Only players may be affected by this command`.
- Используются `WrapperPlayServerShowDialog`, `WrapperPlayClientCustomClickAction` и `WrapperPlayServerClearDialog`.
- Paper получает игрока напрямую через PacketEvents `PlayerManager`, без ручной подмены версии клиента.
- `packetevents-spigot-2.13.0.jar` скачивается с официального релиза и проверяется по SHA-256.
- После первой автоматической установки сервер выводит понятное сообщение и требует один обычный перезапуск.
- Отключение игрока безопасно очищает форму даже после освобождения PacketEvents channel/user.
- Folia-события, title, телепортация и доставка результата выполняются через корректный player/region scheduler.

## Native dialogs и обработка пароля

- Одна модель `PlayerDialog` используется на Velocity, BungeeCord и Paper/Folia.
- Поддерживаются формы входа и регистрации, повтор пароля и динамические действия.
- PacketEvents использует согласованную с подключением ClientVersion; pnAuth больше не принуждает устаревшую версию протокола.
- ItemStack и dialog mapping совместимы с современными клиентами Minecraft, включая календарную версию 26.2.
- Submit больше не означает простое закрытие окна: значения полей декодируются, проверяются и передаются в `AuthCommandService`.
- Повторная отправка одной формы защищена от параллельной обработки.
- Устаревшие ответы предыдущей UI-сессии игнорируются.

## Новое действие `<auth:open_dialog>`

Интерактивное сообщение полностью задаётся одной строкой локализации:

```yaml
dialog:
  error: "<dark_gray>[<light_purple><bold>pnAuth</bold></light_purple>]</dark_gray> <red>{error}</red> <gray>Окно закрыто.</gray> <auth:open_dialog><hover:show_text:'<gray>Нажмите, чтобы снова открыть окно</gray>'><gradient:#a855f7:#38bdf8><bold>[Повторить вход]</bold></gradient></hover></auth>"
```

- `<auth:open_dialog>` преобразуется в client custom action `pnauth:open_dialog`.
- Нажатие больше не выполняет `/_pnauthui open` и не засоряет журнал команд сервера.
- Действие маршрутизируется PacketEvents и проверяется по UUID активного подключения.
- Hover, gradient, bold и остальное MiniMessage-оформление сохраняются.
- Интерактивная строка работает при глобальном формате `MINI_MESSAGE`, `LEGACY`, `JSON` или `PLAIN`.
- Неизвестное pnAuth-действие отклоняется с понятным предупреждением и списком доступных действий.

## Title, subtitle и анимация

- `ui.processing-title.enabled` включает анимацию только во время фактической проверки пароля.
- Доступны типы `NONE`, `GRADIENT` и `FRAMES`.
- Для градиента настраиваются палитра и количество кадров.
- Для `FRAMES` можно перечислить готовые пользовательские кадры с `{text}`.
- `frame-interval-ticks` управляет скоростью анимации.
- `minimum-display-millis` не позволяет быстрой локальной проверке мгновенно скрыть индикатор.
- Успешный вход, успешная регистрация и ошибка имеют отдельные title/subtitle из локализации.
- `result-fade-in-millis`, `result-display-millis` и `result-fade-out-millis` управляют итоговым экраном.
- Анимация завершается без принудительного мерцания и освобождает server-side handle безопасно.

## Сообщения и компоненты

- Общий Adventure-конвейер обновлён до версии, используемой PacketEvents 2.13.x.
- Исправлена BungeeCord-совместимость serializer SPI без упаковки конфликтующей второй копии Adventure API.
- Форматированное значение `{error}` сначала преобразуется в безопасный видимый текст.
- В чат больше не попадают строки вида `\\<gradient...>`, `\\<red>` или закрывающие MiniMessage-теги.
- Все системные сообщения берутся из `messages_ru.yml` или `messages_en.yml`.
- Поддерживаются MiniMessage, Adventure JSON, legacy `&`, нативный `§`, HEX/RGB, hover и click/custom actions.
- Старые отдельные `dialog.retry` и `dialog.retry_hover` автоматически объединяются в единый `dialog.error` с резервной копией файла.

## Команды и перезагрузка

- `pnauth reload` и `/pnauth reload` перезагружают конфигурацию без завершения процесса Hub или сервера.
- Консоль не проверяется как игрок и не требует игрового permission.
- Игроку требуется `pnauth.admin.reload`.
- Новый конфиг сначала полностью проверяется; при ошибке рабочий runtime продолжает использовать прежние значения.
- Сообщения, storage, limbo, verification и cluster transport пересоздаются только после успешной проверки.

Основные команды:

- `/register`, `/reg` — регистрация;
- `/login`, `/l` — вход;
- `/logout` — завершение сессии;
- `/changepassword`, `/changepass` — смена пароля;
- `/unregister`, `/unreg` — удаление аккаунта;
- `/totp`, `/2fa` — управление вторым фактором;
- `/status` — состояние авторизации;
- `/auth`, `/pnauth` — общий корень и административные операции.

## Возможности pnAuth

- PBKDF2, BCrypt и Argon2, автоматический rehash паролей.
- TOTP 2FA, recovery-коды, ограничение попыток и lockout.
- Trusted IP sessions с отзывом после смены пароля.
- CAPTCHA, лимиты аккаунтов по IP и блокировка действий до входа.
- Встроенный PicoLimbo, auth/backend routing и forced hosts.
- SQLite для одиночной установки; MySQL, MariaDB и PostgreSQL для сети.
- Режимы `STANDALONE`, `SHARED_DATABASE`, `REDIS` и `HUB`.
- Долговечный cluster outbox с at-least-once доставкой и идемпотентной обработкой.
- Discord, Telegram, VK и custom HTTPS verification provider.
- HMAC-SHA256, timestamp, nonce, replay protection и запрет credentials в cluster events.
- Самостоятельная Paper/Folia-авторизация с блокировкой движения, чата, команд, взаимодействий и инвентаря.
- Возврат после входа в `ORIGINAL`, `SPAWN`, `CUSTOM` или режим `NONE`.

## Установка

1. Скачайте `pnAuth-1.1.0.jar`.
2. Поместите его в `plugins` Velocity, BungeeCord или Paper/Folia.
3. Запустите сервер. Если PacketEvents отсутствует, pnAuth скачает и проверит подходящий JAR.
4. После первой автоматической установки PacketEvents запустите сервер повторно.
5. Настройте `plugins/pnAuth/config.yml` и файлы в `plugins/pnAuth/messages`.

Для ручной установки используется PacketEvents 2.13.0 соответствующей платформы.

## pnAuth Hub

Hub хранит и проверяет password hash, TOTP secret и recovery-коды централизованно. Игровые узлы не получают password hash.

```bash
java -jar pnAuth-hub-1.1.0.jar /path/to/pnauth-hub
```

Для production рекомендуется слушать `127.0.0.1` и публиковать API через HTTPS reverse proxy.

## Требования

- Java 21+ для Minecraft 1.21.x.
- Java 25 для актуальных Paper/Velocity 26.x.
- PacketEvents 2.13.0.
- Клиент с поддержкой native dialogs.
- HTTPS для Hub и внешних verification providers.

## Обновление с 1.0.0

1. Остановите сервер или proxy.
2. Сделайте резервную копию базы и `plugins/pnAuth`.
3. Замените `pnAuth-1.0.0.jar` на `pnAuth-1.1.0.jar`.
4. Не удаляйте конфигурацию: отсутствующие ключи и платформенная секция PacketEvents будут добавлены миграцией.
5. Выполните полный запуск; обычного `/reload` для замены JAR недостаточно.

Формат базы и пользовательские аккаунты совместимы с 1.0.0.

## Комплект релиза

- `pnAuth-hub-1.1.0.jar` — центральный сервис сети.
