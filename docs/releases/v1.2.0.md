# pnAuth 1.2.0 — Multi-Server Routing & Independent Limbo

pnAuth 1.2.0 — обновление маршрутизации авторизации для Velocity и BungeeCord. Главная цель релиза — убрать жёсткую привязку auth-сервера к встроенному Limbo, сделать группы auth/backend серверов полноценными и понятными, добавить индивидуальный online-лимит для каждой точки маршрутизации и заменить нечитабельные ошибки конфигурации на конкретные диагностические сообщения.

Один `pnAuth-1.2.0.jar` работает на Velocity, BungeeCord, Paper и Folia. Для сетевой архитектуры отдельно поставляется `pnAuth-hub-1.2.0.jar`.

## Главное в 1.2.0

- Встроенный Limbo больше не обязан совпадать с auth-сервером.
- `servers.auth` поддерживает любое количество обычных Minecraft auth-серверов и при необходимости маршрут встроенного Limbo.
- `servers.backend` поддерживает любое количество lobby/hub серверов после успешной авторизации.
- Каждый сервер описывается как `{ server, online }`; лимит хранится рядом с сервером, а не в отдельной несвязанной карте.
- Балансировка работает по всему пулу auth и backend серверов.
- Добавлен и поддерживается режим `LOWEST_LOAD_PERCENT` наряду с `LEAST_PLAYERS`, `FIRST_AVAILABLE`, `ROUND_ROBIN`, `RANDOM` и `FILLING`.
- Старые конфиги автоматически мигрируются в новую схему с резервной копией.
- Ошибки отсутствующих auth/backend серверов теперь указывают конкретное имя и место, которое нужно исправить.
- Native dialogs, captcha, reminders и ограничения работают на любом сервере из auth-пула, а не только на первом.

## Новая структура серверов

Старые одиночные поля `auth-server` и `backend-server` больше не являются основной моделью конфигурации. В актуальном YAML используются группы серверов.

```yaml
servers:
  auth:
    - server: auth-1
      online: 100
    - server: auth-2
      online: 150
    - server: auth-limbo
      online: 300

  backend:
    - server: lobby-1
      online: 200
    - server: lobby-2
      online: 250

  balancer-mode: LEAST_PLAYERS
  require-auth-before-server: true
```

`servers.auth` — точки, в которых игрок находится до завершения авторизации. Это могут быть обычные Minecraft-серверы, встроенный Limbo либо их сочетание.

`servers.backend` — точки входа после успешной авторизации: lobby, hub и другие основные серверы сети. После попадания туда игрок уже может выбирать режим или сервер средствами самой сети.

Поле `online` задаёт индивидуальную вместимость сервера и используется режимами балансировки, которым нужен лимит нагрузки.

## Limbo больше не управляет auth-пулом

Раньше при `limbo.enabled: true` pnAuth требовал, чтобы auth-server совпадал с `limbo.server-name`. Это искусственное ограничение удалено.

Теперь Limbo — отдельный proxy route:

```yaml
limbo:
  enabled: true
  server-name: auth-limbo
```

Чтобы использовать его как одну из точек авторизации, достаточно добавить `auth-limbo` в `servers.auth`. Если не добавлять, Limbo останется доступным маршрутом, а pnAuth будет использовать обычные auth-серверы.

Таким образом поддерживаются все варианты:

- только обычный auth-сервер;
- несколько обычных auth-серверов;
- только встроенный Limbo;
- Limbo вместе с обычными auth-серверами.

## Балансировка

Один механизм выбора используется для auth и backend пулов. Поддерживаются:

- `LEAST_PLAYERS` — сервер с минимальным текущим онлайном;
- `LOWEST_LOAD_PERCENT` — сервер с минимальной долей заполнения относительно `online`;
- `FIRST_AVAILABLE` — первый доступный сервер;
- `ROUND_ROBIN` — последовательное распределение;
- `RANDOM` — случайный доступный сервер;
- `FILLING` — последовательное заполнение серверов до их индивидуального лимита.

`forced-hosts` продолжает иметь приоритет при выборе backend, если для текущего домена задана конкретная цель.

## Проверка конфигурации

Перед запуском pnAuth проверяет все маршруты.

Для Velocity проверяются:

- каждый сервер из `servers.auth`;
- каждый сервер из `servers.backend`;
- каждая цель `servers.forced-hosts`;
- исключение для встроенного Limbo, если имя auth-маршрута совпадает с `limbo.server-name` и Limbo включён.

Для BungeeCord выполняется аналогичная проверка зарегистрированных `ServerInfo`.

Вместо общего stack trace пользователь получает конкретную ошибку, например:

```text
pnAuth configuration error:
Invalid server routing configuration:
 - Auth server 'auth-2' from servers.auth is not registered in velocity.toml.
```

Ошибки пустого имени сервера, дубликатов, пересечения auth/backend групп и `online <= 0` также сообщают конкретный путь настройки и проблемное значение.

## Миграция конфигурации

Схема конфигурации обновлена до версии 13.

При загрузке старого конфига pnAuth переносит прежние поля `auth-server`, `auth-servers`, `backend-server`, `backend-servers`, `max-players-per-server` и `server-limits` в структурированные группы серверов.

Перед автоматической перезаписью существующего файла создаётся `config.yml.bak`.

Пользовательские online-лимиты сохраняются при миграции, а старые одиночные значения превращаются в обычные элементы нового списка.

## Auth UI на нескольких серверах

В 1.2.0 все проверки, которые раньше ориентировались только на первый `auth-server`, переведены на полный auth-пул.

Это относится к:

- разрешению переходов до авторизации;
- выбору первоначального auth-сервера;
- перенаправлению при попытке уйти на backend;
- native dialogs;
- CAPTCHA;
- напоминаниям о регистрации/входе;
- обработке kick с auth-сервера;
- BungeeCord и Velocity listeners.

Игрок может попасть на любой auth-сервер из группы, и pnAuth будет считать его корректной точкой авторизации.

## Совместимость

- База аккаунтов не меняется.
- Пароли, TOTP, recovery-коды и сессии совместимы с 1.1.0.
- Старый YAML мигрируется автоматически.
- Внутренние compatibility accessors для первого auth/backend сервера сохранены там, где это необходимо старому API-коду.
- Embedded PicoLimbo остаётся опциональным.

## Обновление с 1.1.0

1. Остановите proxy/server.
2. Сделайте резервную копию базы и каталога `plugins/pnAuth`.
3. Замените `pnAuth-1.1.0.jar` на `pnAuth-1.2.0.jar`.
4. Запустите pnAuth один раз и проверьте мигрированный `config.yml`.
5. Убедитесь, что все имена из `servers.auth` и `servers.backend` зарегистрированы в `velocity.toml` или BungeeCord config.
6. Если используете встроенный Limbo как auth-route, добавьте его `server-name` в `servers.auth`.

## Комплект релиза

- `pnAuth-1.2.0.jar` — единый игровой плагин.
- `pnAuth-hub-1.2.0.jar` — центральный сервис сети.
- `SHA256SUMS.txt` — контрольные суммы обоих JAR.

Перед публикацией release workflow выполняет тесты shared-модуля, production shadow-сборку, проверку runtime layout и формирует SHA-256 для релизных файлов.
